# LMForge v0.3.0 — re-ranking correctness

This release fixes `/v1/rerank` on every platform. **It changes the scale of
`relevance_score`.** Clients that compare scores against a fixed threshold must
re-tune it.

## Breaking: rerank scores are now probabilities

Up to v0.2.0, LMForge passed every engine score through a sigmoid. The engines
already return probabilities for Qwen3-Reranker, so every score was squeezed
into **[0.5, 0.731]**. Ranking order was preserved, but absolute values were not
meaningful.

From v0.3.0, `relevance_score` is a calibrated relevance probability in [0, 1]
on every engine, and responses carry `"score_type": "probability"`:

| Engine | Model | Engine returns | LMForge applies |
|---|---|---|---|
| oMLX (macOS) | any reranker | probability | nothing (pass-through) |
| llama.cpp | Qwen3-Reranker | probability (yes/no softmax) | nothing (pass-through) |
| llama.cpp | bge-reranker-v2-m3, jina-reranker-v2 | logit | sigmoid |

The same document pair, before and after (oMLX 0.7.0):

| | v0.2.0 | v0.3.0 |
|---|---|---|
| relevant | 0.6663 | 0.6914 |
| irrelevant | 0.5000054 | 0.0000215 |

**Action:** re-tune score thresholds. A threshold of 0.55 on the old scale
corresponds to about 0.2 on the new one. Rankings and `top_n` results are
unchanged on macOS.

## Fixed: Qwen3-Reranker on Linux / Windows (llama.cpp) scored every document 0.5

The catalog's `qwen3-reranker:*` GGUF shortcuts pointed at mradermacher
conversions. These files have no reranker head (no `cls.output.weight`), so
llama.cpp gave every document the same score, which surfaced as 0.5000000.

- The shortcuts now point at GGUFs converted by llama.cpp's
  `convert_hf_to_gguf.py`, each verified by reading the file header:
  - `qwen3-reranker:0.6b:8bit` → `ggml-org/Qwen3-Reranker-0.6B-Q8_0-GGUF`
  - every other size and quant → `giladgd/Qwen3-Reranker-*-GGUF`
- `lmforge pull` refuses a reranker GGUF without a head.
- `/v1/rerank` answers **422 `reranker_unusable`** for such a file instead of
  returning meaningless scores.
- `lmforge doctor`, `lmforge models list` and `lmforge pull <id>` flag installs
  made by earlier versions.

### Re-pull the reranker (Linux / Windows)

If you pulled any `qwen3-reranker:*` shortcut before v0.3.0, upgrade LMForge
first, then run:

```bash
lmforge models remove qwen3-reranker:0.6b:8bit
lmforge pull qwen3-reranker:0.6b:8bit
```

Use your own shortcut if it differs. Upgrading with `install-core` refreshes the
model catalog. If you upgrade the binary some other way, run `lmforge init`
before re-pulling. To check an install, run `lmforge doctor`: it lists any
unusable reranker under "Rerankers — unusable GGUF installs".

macOS (oMLX) installs need no re-pull.

## Fixed: long documents failed the whole rerank request on llama.cpp

llama-server processed rerank pairs in 512-token micro-batches. A single
query+document pair longer than that returned HTTP 500 for the entire request.

- llama.cpp now runs rerank models and BERT-style embedders (bge-m3, nomic)
  with a 2048-token batch (`LMFORGE_LLAMACPP_POOLING_BATCH`, capped at the
  model's trained context), so they accept inputs up to 2048 tokens instead of
  512. Raising it raises host-RAM use: llama-server holds about
  `batch × vocab × 4 bytes` while running such an input (~2 GiB for bge-m3 at
  2048).
- A document that is still too long is truncated from the end. Its index is
  listed in `meta.truncated_documents`, and the request succeeds. On macOS,
  oMLX truncates inside the engine.
- A query that alone leaves no room for a document returns **400
  `query_too_long`**.
- An oversize error from the engine returns **400 `input_too_long`** instead of
  500.

## Other changes

- **Embedding VRAM.** On GPU, embedding models now load with an 8192-token
  context (`LMFORGE_LLAMACPP_EMBED_CTX`; capped at the trained context) instead
  of their full trained context. Qwen3-Embedding-0.6B drops from 4.7 GB to
  2.0 GB of VRAM. An embedding input longer than the context returns 400
  `input_too_long` (it used to be an engine 500).
- **Two LMForge instances no longer kill each other.** The engine port is now
  the API port + 1 (`LMFORGE_ENGINE_PORT` overrides it). Startup only stops a
  stale process that belongs to the same instance; a port held by anything else
  is reported and left running.
- Rerank GPU loads on llama.cpp size their context to 4 × the batch. This cuts
  the Qwen3-Reranker-0.6B KV cache from 4.4 GiB to 0.9 GiB. The larger batch
  adds about 1 GiB of compute buffer for that model.
- The oMLX engine entry now records 0.7.0 as the tested and last-known-good
  release (full macOS E2E passed). It serves the catalog's Qwen3-Reranker
  (mxfp8).
- E2E TC-E11 now checks that each reranker family ranks a clearly relevant
  document above an irrelevant one. A model that scores every document the same
  now fails the gate.
